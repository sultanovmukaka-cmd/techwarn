# Правила разработки (Rules)

## 1. Чистота кода и архитектура
- Компонентный подход React с разделением ответственности (UI-компоненты, карта, хуки, утилиты, моковые данные).
- Чистый, семантический HTML5 и современный CSS с адаптивной сеткой (Flexbox, Grid, CSS-переменные).
- Отсутствие неиспользуемого кода, консольных спам-логов и синтаксических ошибок.

## 2. Производительность и UX
- Быстрый отклик интерфейса без зависаний карты.
- Корректная очистка и инициализация экземпляра Leaflet при монтировании/размонтировании компонентов React во избежание утечек памяти ("Map container is already initialized").
- Очевидный визуальный фидбек на любые действия пользователя (ховеры, клики, фильтрация).

## 3. Мобильная адаптивность
- Touch-friendly элементы (кнопки с областью нажатия не менее 44x44px).
- Корректное скрытие/раскрытие сайдбара на мобильных устройствах, чтобы карта оставалась управляемой.

## 4. Консистентность данных
- Единая схема данных для каждого инцидента (`id`, `title`, `type`, `status`, `severity`, `coordinates`, `address`, `description`, `reportedAt`, `estimatedResolution`, `affectedCount`, `serviceTeam`).
